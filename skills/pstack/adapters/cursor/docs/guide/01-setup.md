# Set up canonical Pstack

Use the Shipshit distribution and its canonical companion skills. This adapted
guide does not install or require the original Pstack plugin.

## Resolve the installation

Use the target harness's supported skill installer to make canonical pstack,
its required companions and setup-pstack available. Inspect existing
registrations first. Preserve unrelated skills and the user's selected role
configuration. Installation alone does not register hooks, create routines or
make Pstack sticky for every conversation.

## Configure selected adapters

Run setup-pstack through the active catalog when configuration is requested.
It identifies the canonical configuration source, including any generator that
owns derived files. Review its exact adapter plan and rollback before applying
authorized changes.

The distribution supplies no fixed model panel. Keep existing role assignments,
provider opt-ins and effort choices. A missing role is unresolved configuration.
Use an authorized parent-native route when the harness policy permits it, or
report the missing route. Do not delete configured rows to restore imaginary
skill defaults or create a second model file beside the existing source.

The inherit-parent and auto aliases are routing choices only where the active
harness supports that meaning. They are not model IDs and do not guarantee
diversity. Report which panel lanes actually ran and any lost coverage.
Setup probes only selected, authorized lanes on the approved host.

## Verify discovery and behavior

Start a fresh session in the intended project. Confirm canonical entrypoints
resolve and exercise one representative workflow. Disable a duplicate upstream
registration only after its replacement works and within the authorized migration.

If the project needs a verification skill, request create-verification-skill
separately. It writes to the project skill root selected by the harness, with
Launch, Doctor, Drive, Evidence and Cleanup instructions and a feature map.
A failed proof leaves the result unverified.
[Verify and ship](06-verify-and-ship.md#create-a-project-verification-skill)
explains that workflow.

## Run a scoped task

Ask Pstack to add a JSON output flag to a named command while keeping its text
output byte-identical, then verify both modes.

The matched playbook supplies the steps; the task and harness supply authority
and execution choices. Follow-up messages retain that task's scope. Default
activation in future sessions requires an explicitly configured adapter.
