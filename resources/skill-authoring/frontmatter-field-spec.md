# Frontmatter Field Specification

Field-by-field reference, merged from the agentskills.io base spec and the Claude Code extension fields. Sourced 2026-06-12. `name` and `description` are the only required fields; everything else is an optional capability extension.

| Field | Required | Purpose | Constraints |
|-------|----------|---------|-------------|
| `name` | **Yes** | Display label for the skill in listings. For plugin-root SKILL.md files (no parent directory name), also determines the command name. For directory-based skills, the directory name sets the slash command regardless of this field. | Max 64 characters. Lowercase letters, numbers, and hyphens only. Must not start or end with a hyphen. No consecutive hyphens (--). No XML tags. No reserved words: 'anthropic', 'claude'. Must match the parent directory name (for directory-based skills). |
| `description` | **Yes** | Primary automatic-triggering signal. Claude loads only name+description at startup for all installed skills to decide which skill is relevant. The combined description+when_to_use text is truncated at 1,536 characters in the skill listing. | Must be non-empty. Max 1,024 characters. No XML tags. Write in third person. Include both capability (what it does) and trigger context (when to use it). Front-load key terms due to truncation. |
| `when_to_use` | No | Supplementary trigger phrases or example requests that extend the description. Appended to description in the skill listing. | Shares the 1,536-character combined cap with description. Content after the cap is silently truncated. |
| `disable-model-invocation` | No | When true: removes skill description from Claude's context (Claude cannot see or auto-trigger the skill) and prevents preloading into subagents. The full skill body still loads when the user manually invokes via /skill-name. | Boolean. Default: false. Use for side-effectful workflows (deploy, commit, send messages). |
| `user-invocable` | No | When false: hides the skill from the / command menu. Claude can still load the skill automatically when the description matches. Does NOT block Skill tool access. | Boolean. Default: true. Setting both user-invocable: false and disable-model-invocation: true leaves the skill unreachable from all paths. |
| `context` | No | When set to 'fork': runs the skill in an isolated subagent with no conversation history access. Skill content becomes the subagent's entire prompt. | Valid value: 'fork'. Only use for skills with explicit actionable task instructions. Skills with guidelines only (no task) return empty output from a forked subagent. Note: as of June 2026, a known GitHub issue (#17283) indicates context:fork may not be fully honored when skills are invoked via the Skill tool. |
| `paths` | No | Documented to limit automatic activation to files matching glob patterns. Intended for path-scoped skill activation. | Comma-separated string or YAML list of glob patterns. CAUTION: As of v2.1.84, this field has an active bug (issue #49835) — skills with paths set become completely undiscoverable. For monorepo scoping, use nested .claude/skills/ directories within packages instead. |
| `hooks` | No | Lifecycle hooks scoped to this skill's active period only. Hooks are cleaned up when the skill finishes. | See Claude Code Hooks documentation for configuration format. |
| `argument-hint` | No | Hint shown during autocomplete to indicate expected arguments. | String. Example values: '[issue-number]' or '[filename] [format]'. |
| `allowed-tools` | No | Grants per-use-approval bypass for listed tools while the skill is active. Does not restrict other tools — every tool remains callable. For project skills, takes effect only after the user accepts the workspace trust dialog. | Space- or comma-separated string, or YAML list. Use fully qualified ServerName:tool_name for MCP tools. Labeled as 'experimental' in the agentskills.io spec. |
| `disallowed-tools` | No | Removes specific tools from Claude's available pool while the skill is active. Restriction clears when the user sends their next message. | Space- or comma-separated string, or YAML list. Use for autonomous loop skills that must never call certain tools (e.g., AskUserQuestion). |
| `compatibility` | No | Declares specific environment requirements such as system packages, network access needs, or target agent product. | Max 500 characters. Most skills do not need this field. Include only when the skill has genuine environment prerequisites. |

## Notes that bite

- The combined `description` + `when_to_use` text is hard-capped at 1,536 characters in the skill listing — content past the cap is silently dropped, taking trigger keywords with it. Front-load the description.
- Setting both `user-invocable: false` **and** `disable-model-invocation: true` makes the skill unreachable from every path. Pick at most one gate.
- `paths` and `context: fork` each have open runtime bugs as of June 2026 — see [checklist.md](checklist.md#open-questions--known-issues) before relying on them.
- `allowed-tools` is an **auto-approve allowlist, not a sandbox**: a tool that is not listed is still callable; it just falls through to the normal permission prompt. To actually block a tool, use `disallowed-tools` (Claude) or deny rules / hooks. See [anthropic.md](anthropic.md#tool-permissions-allowed-tools--disallowed-tools).
