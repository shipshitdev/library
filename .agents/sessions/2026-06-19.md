## Session 1: Adopt EARS acceptance-criteria syntax across PRD/spec skills

### Summary

Started from a question about the vitaeai skills not present in this repo, which
led into the PRD pipeline. Found a real seam (`Success Criteria` vs
`Acceptance Criteria`), researched the 2026 standard for agent-read specs, and
standardized the PRD/spec skills on **EARS** acceptance criteria. Shipped as
[PR #35](https://github.com/shipshitdev/skills/pull/35).

### Key decisions

| Decision | Rationale |
|----------|-----------|
| Standardize acceptance criteria on EARS | Skills are read by AI coding agents; vague prose → drift. EARS is the de-facto agent-spec grammar. |
| Canonical section = `Acceptance Criteria` (EARS) | Resolves the writing-prds/gate naming seam; `Success Criteria` (build-correctness, not KPI) folded in. |
| Testing bar lives in `Verification Plan`, not Acceptance Criteria | De-duplicates feature-intake; keeps Acceptance Criteria purely behavioral/EARS. |
| Gate stays warning-only by default | Non-breaking adoption; the regex is the single point to adjust if EARS falls out of favor (it's Kiro-origin, not ratified). |
| Don't port vitaeai skills | PostHog pack is product-specific; ShipCode/Vitae skills are project-hardwired. |
